# Addressables 패치 직접 확인하기

이 저장소를 받은 사람이 두 가지를 확인하는 방법이다.

1. 작성자가 Unity CCD(Cloud Content Delivery)에 올려 둔 콘텐츠를 실제로 받아 오는지
2. 콘텐츠 버전을 바꿨을 때 앱이 카탈로그를 갱신하고 바뀐 번들만 받는지(겨울 v1 → 봄 v2)

CCD에는 작성자만 올릴 수 있다. 받은 사람은 CCD에서 **받기만** 하고, 버전을 바꿔 보는 테스트는 **자기 PC의 로컬 콘텐츠 서버**로 한다. 계정이나 키는 필요 없다.

## 준비

- Unity 6000.3.9f1(Windows Build Support. Android 기기로 볼 때는 Android Build Support).
- 저장소와 `content/v2` 브랜치를 함께 받는다.

```bash
git clone <저장소 주소>
```

```bash
git fetch origin content/v2
```

- Unity로 프로젝트를 열고 **Tools ▸ Addressables Delivery ▸ 빌드 창**을 연다. 이후 작업은 모두 이 창에서 한다. 창 맨 위 **상태**에 현재 플랫폼, 프로필, Addressables 빌드 상태가 나온다.

## 1. CCD 연결 확인 (작성자 CCD, 읽기 전용)

1. 빌드 창 **CCD** 칸에서 **연결 확인 (카탈로그 해시 받기)**를 누른다. 키가 필요 없다.
2. 배지마다 카탈로그 해시가 나오면 연결된 것이다.
   - `v1`: 겨울 콘텐츠, `v2`: 봄 콘텐츠, `latest`: 가장 최근 릴리스(지금은 v2).
   - `404 (파일 또는 릴리스 없음)`은 그 플랫폼에 아직 올리지 않은 버전이다.

앱에서 받는 과정까지 보려면 작성자가 배포한 개발 빌드(Windows 실행 파일, Android APK)를 쓴다.

1. 처음 실행하면 `v1`(겨울)을 받는다. 패치 팝업 → 로비에 겨울 배너가 보인다.
2. 오른쪽 위 **테스트 메뉴 ▸ CCD 콘텐츠**를 눌러 `v2`로 바꾸고 앱을 완전히 껐다 다시 켠다.
3. 카탈로그가 갱신되고 바뀐 번들만 받는다. 봄 배너, 엠버 메이지의 "봄 축제" 코스튬, 챕터 2(수정 9개)를 확인한다.
4. 같은 방법으로 `v1`로 되돌릴 수 있다. 출시 빌드는 테스트 메뉴가 없고 항상 `latest`를 받는다.

소스에서 직접 빌드한 플레이어도 CCD 프로필이면 작성자 CCD에서 받는다. 이때는 자기 PC에서 만든 로컬 번들이 작성자 빌드와 같아야 한다(같은 Unity 버전과 같은 커밋이면 같게 나오는 것을 전제로 하며, 다른 PC에서는 확인하지 않았다).

## 2. 로컬에서 버전 바꿔 보기 (LocalServer)

PC 안의 콘텐츠 서버(`http://localhost:8080`)를 원격 서버로 쓴다. Windows 기준이다.

1. **프로필**을 `LocalServer`로 바꾼다.
2. **전체 빌드 (기준 갱신)** → **Windows 개발 빌드**. 이 실행 파일이 "v1을 설치한 사용자"다.
3. **콘텐츠 서버 ▸ 시작**. 빌드 창이 켜져 있는 동안 `ServerData/`를 내보내고, 요청마다 받은 번들을 콘솔에 남긴다.
4. `Builds/Windows/LobbyFlow.exe`를 실행한다. 패치 팝업 → 겨울 배너 → 챕터 2 추가 다운로드를 확인하고 끈다.
5. 원격 콘텐츠만 v2로 바꾼다. 브랜치는 바꾸지 않는다.

```bash
git restore --source=origin/content/v2 -- Assets/LobbyFlowContent/Remote
```

6. Unity 창을 눌러 바뀐 파일을 읽게 한 뒤 **콘텐츠 업데이트 빌드**. 전체 빌드를 누르면 2번의 기준이 지워지니 누르지 않는다.
7. 4번의 실행 파일을 다시 켠다. 패치 팝업이 뜨고 봄 콘텐츠로 바뀐다. Unity 콘솔의 `[ContentServer] 200 …` 줄에서 바뀐 번들만 받은 것을 볼 수 있다.

되돌리기:

```bash
git restore -- Assets/LobbyFlowContent/Remote
```

```bash
git clean -fd -- Assets/LobbyFlowContent/Remote
```

프로필을 바꾸면 `AddressableAssetSettings.asset`이 바뀐다. 끝나면 프로필을 `CCD`로 돌려 두거나 그 파일도 되돌린다.

## 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 빌드 창 상태가 노란 경고 | 이 플랫폼의 Addressables 빌드가 현재 프로필과 다르다. 전체 빌드를 다시 한다 |
| 플레이어 빌드 버튼이 꺼져 있음 | 위와 같거나, 현재 플랫폼이 버튼의 플랫폼과 다르다(File ▸ Build Profiles에서 전환) |
| 앱이 "카탈로그 확인 실패" | LocalServer면 콘텐츠 서버가 꺼져 있다. CCD면 인터넷 연결을 확인한다 |
| 업로드 버튼이 없음 | 정상이다. 업로드는 작성자의 서비스 계정 키가 있어야 한다 |
| v2로 바꿨는데 그대로 | 테스트 메뉴의 "Boot 다시 실행"이 아니라 앱을 완전히 다시 시작해야 한다 |
