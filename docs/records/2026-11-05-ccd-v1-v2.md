| 업로드 | 메뉴 **CCD ▸ 현재 플랫폼 업로드와 릴리스** → `ugs ccd entries sync … -r`(UGS CLI 2.0, 서비스 계정) |

## CCD 상태

| 단계 | 릴리스 | `latest` 배지 | 카탈로그 해시 |
|---|---|---|---|
| v1 전체 빌드 업로드 | 1 | 릴리스 1 | `54f4d144…` |
| v2 업데이트 빌드 업로드 | 2 | 릴리스 2로 자동 이동 | `0200432b…` |

- 배지를 따로 지정하지 않아도 CCD가 새 릴리스에 `latest`를 옮겼다.
- 공개 주소(`…/release_by_badge/latest/entry_by_path/content/?path=/파일`)에서 카탈로그 해시와 번들을 인증 없이 받았다(curl, 200). 받은 해시는 로컬 빌드 결과와 같았다.
- 업로드는 지우기 옵션 없이 해서 릴리스 2에도 v1 번들이 남는다. 이전 카탈로그를 가진 플레이어가 계속 받을 수 있다.

## 배지 전환 (Windows, 개발 빌드)

CCD 릴리스에 `v1`(릴리스 1), `v2`(릴리스 2) 배지를 붙이고, 개발 빌드의 테스트 메뉴 **CCD 콘텐츠**로 받을 배지를 바꿨다. 플레이어는 Boot·로비 씬만 다시 만든 뒤 빌드했다(Addressables 빌드는 그대로).

| 실행 | 배지 | 결과(`Player.log`) |
|---|---|---|
| 1 | v1(기본) | 이전에 받아 둔 v2 카탈로그에서 `카탈로그 변경 1개, 갱신한다` → `갱신 True` → 코스튬 3(v1로 내려감). 캐시 삭제 뒤 Boot에서 0.1MB 받기, 챕터 2 받기. 테스트 메뉴에서 `CCD 콘텐츠 v2 선택(현재 실행은 v1)` |
| 2 | v2(앱 재시작) | `카탈로그 변경 1개, 갱신한다` → `갱신 True, 받을 크기 0.1MB` → 코스튬 4. 챕터 2 다시 받기 |

- 배지를 바꾸면 v1 → v2뿐 아니라 v2 → v1로도 카탈로그가 바뀐다. Addressables는 원격 카탈로그 해시가 캐시된 것과 다르면 방향과 상관없이 갱신한다.
- 화면 확인(겨울 → 봄)은 사용자가 했다.
